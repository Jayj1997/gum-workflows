# README 更新规范：模块完成后的进度同步

## 目的

每完成一个独立开发模块，都要把 README 从“上一版本的状态快照”更新为“当前可验证事实”。README 面向第一次接触项目的人，负责说明项目是什么、接下来做什么、已经完成什么；详细合同、票据和验证证据继续保存在设计文档、`.scratch/<module>/` 与测试中。

本规范在以下情况触发：

- 一个有独立 spec 和 tickets 的模块完成；
- 模块状态从设计中或实施中变为已完成；
- 已实现能力、平台边界或下一阶段顺序发生实质变化。

## README 固定结构

README 保持以下主结构，按人类阅读顺序组织：

1. **项目名字**：只保留项目名称。
2. **项目概述**：用短段落回答项目服务谁、解决什么问题、核心运行方式和产品方向。
3. **项目规划**：只写尚未实施的方向、明确后置项和对应详细计划入口。
4. **项目当前进展**：按“最新完成优先”记录历史模块，每个模块使用“模块名 — 已完成”标题、一个概述段落和一组关键交付。
5. **使用与文档**：只保留最短可执行命令、示例入口和权威文档导航。

代码块只用于可复制执行的命令。领域关系、流程和模块概述优先使用短段落或列表；只有关系无法用简短文字说明时才使用表格或图。

## 更新步骤

### 1. 建立事实基线

阅读刚完成模块的 spec、全部 tickets、验收评论、当前实现文档和测试。确认每项 README 声明都属于以下之一：

- 已由实现和测试证明的当前能力；
- 已确认但尚未实施的产品规划；
- 明确的平台限制或后置范围。

完成标准：模块的交付、限制、验证平台和未完成项都能指向当前仓库证据。

### 2. 更新项目概述与规划

项目定位未变化时只做必要修订。把刚完成的内容从“项目规划”移到“项目当前进展”，规划中只保留未来工作。详细阶段顺序链接到权威计划，不在 README 复制长篇设计。

完成标准：同一能力不会同时被描述为“已完成”和“待实现”。

### 3. 添加历史模块记录

在“项目当前进展”顶部新增：

```text
### <module-name> — 已完成

<一段说明该模块解决的问题和对产品的推进>

主要交付：
- <用户可理解的能力或边界>
```

关键交付应覆盖领域能力、用户可观察行为、重要平台边界和验证结果。实现类名、私有 helper、逐提交记录与完整票据清单留在详细文档中。

完成标准：不了解代码的读者能在一分钟内理解该模块带来了什么。

### 4. 同步进度文档

按变更范围检查并更新：

- `README.md`：项目级公开状态；
- `AGENTS.md`、`CLAUDE.md`：当前实现边界与后续工作入口；
- `docs/DEVELOPMENT.md`：开发阶段、目录或规范发生变化时更新；
- `docs/domain-model.md`：仅记录已经实现的领域模型；
- 当前产品计划：标注哪些前置能力已完成，保留尚未实施的设计；
- `.scratch/<module>/spec.md`：模块完成时更新顶层状态；
- `CONTEXT.md` 或 ADR：只有领域词汇或重大模型决定变化时更新。

完成标准：使用 `rg` 搜索旧状态词后，不再存在把已完成模块描述为“正在实施”或“尚未实现”的冲突表述。

### 5. 保持诚实边界

README 必须区分业务失败与平台错误、当前平台与目标平台、真实实现与 Mock、保存引用与保存本体、已验证环境与设计上支持的环境。避免把局部工具能力扩写成更宽承诺，例如把 `go vet` 写成完整静态分析，或把一次 Race 通过写成项目不存在数据竞争。

完成标准：每个能力陈述都没有超出 spec、实现和验收证据。

### 6. 验证更新

至少执行：

- `git diff --check`；
- `rg` 搜索模块名、旧状态词、重复待办和失效路径；
- 检查 README 中的相对链接目标存在；
- 若 README 中的命令、示例或公开行为发生变化，运行对应 validate、focused test 或 CLI e2e；
- 确认工作树只包含本次文档同步相关变更。

完成标准：README 结构完整、链接有效、状态一致，验证结果已记录在模块票据或提交说明中。

## 写作准则

- 先写用户获得的能力，再写支撑它的技术机制。
- 每个模块只保留一个概述和一组关键交付，避免按 ticket 或 commit 复述开发过程。
- 使用项目领域词汇，并以 `CONTEXT.md` 为权威。
- 历史模块按最新完成优先排列，保留“已完成”状态，不把旧模块从 README 擦除。
- 未来待办只在“项目规划”维护一份项目级索引；spec 通过链接引用，不复制第二份长期清单。
- 保留真实限制。简洁来自删除重复信息，不来自省略关键边界。
